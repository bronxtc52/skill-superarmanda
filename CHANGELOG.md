## 1.0.2 — 2026-10-04

### Изменено

- `pr_review.py check`: результат CodeRabbit определяется по факту ревью HEAD двумя каналами
  доказательства (review на HEAD; сводный issue comment с маркером завершения и диапазоном, кончающимся на HEAD вне
  блок-цитат, тела review не в счёт) и выдаётся полем `coderabbit` (`pass`/`findings`/`unavailable`/`pending`). `unavailable` —
  только по явному отказу, в теле которого есть диапазон до HEAD (отказ без диапазона — `pending`); ложное «unavailable» больше не останавливает гейт мерджа (#72).
- Пустое ревью CodeRabbit на HEAD — доказательство завершения, а не `incomplete` основного статуса.
- Гейт мерджа: результат роли `coderabbit` `unavailable` на HEAD не блокирует (CodeRabbit необязателен);
  остальные вердикты не менялись, совместимость с гейтом 1.0.0 закреплена тестом по замороженной копии
  (`tests/fixtures/gate-1.0.0/`) (#72).
- `references/pr-review.md`, `SKILL.md` (шаг 7): правило координатора — повторять `check` при
  `pending`, через 30 минут после Codex записать `unavailable` по таймауту.

### Добавлено

- Фикстуры REST-ответов с живых PR (#70, #71, #592) в `tests/fixtures/pr-review/coderabbit/`.

## 1.0.1 — 2026-10-04

### Добавлено

- Сторож фоновых хвостов в окне волны: оболочки Claude, запущенные до `/clear` или ждущие впустую
  дольше 30 мин, — одно событие на эпизод и пометка «⚠ хвосты: N» на дашборде. Факты берутся из
  `ps` (`process_table()`), не из `pgrep -f`; без автоубийства (#68).
- Толчок на простое: при `RUNNING`, полной тишине экрана и журналов (включая агентов) дольше
  `idle_nudge_minutes` (по умолчанию 20, `0` — выключено, настраивается на лету) и без дочерних
  процессов у Claude диспетчер шлёт в окно одно «[wab] Толчок: …» на эпизод. Условия перечитываются под
  замком ввода; неизвестное дерево процессов — толчка нет (#68).
- `PROTOCOL.md`, `references/waves.md`: до `HANDOFF_READY` волна останавливает фоновые задачи и агентов
  (`TaskStop`) или перечисляет их в «В полёте»; ожидание процессов — по PID, `pgrep -f`/`pkill -f`
  по шаблону из собственного цикла ожидания запрещены (#68).

## 1.0.0 — 2026-10-04

Релиз режима волн: всё из таблицы «Что реализовано» в `references/waves.md` закреплено тестами,
строк «нет» в ней не осталось.

### Добавлено

- Офлайн-сквозной тест цепочки из двух волн на подставных `claude`, `gh` и `tmux`
  (`tests/superarmanda-waves-e2e.test.sh`): launch → `BLOCKED` → ответ по политике решений →
  `DONE` → гейт мерджа → мердж → следующая волна от свежей базы → `WAB-CHECKPOINT` → `/clear` →
  `--resume` → `DONE` → `chain-result.md`. Работает настоящий код `wab.py`, `gate.py` и `state.py`,
  сеть и платные инструменты недоступны. Набор падает на мутациях: гейт пропускает красный CI,
  Codex не на HEAD, нет привязки сессии после `/clear`, старая рабочая копия, нет замера
  контекста, нет политики решений. Фикстуры журналов сняты с живого прогона
  (`tests/fixtures/transcripts/`).
- Effort ролей — параметр брифа координатора: по умолчанию tester `medium` (`high` при риске high),
  reader `low` (`references/profiles.md`, `SKILL.md`) (#15).
- `references/waves.md`: волна закрывает разобранные ею треды своего PR, только если мандат прогона
  разрешает это явно. Отказ харнесса ведёт в `BLOCKED`, обходить его нельзя (#43).
- `AGENTS.md`: фикстуры журнала, экрана и ответов сервисов снимаются только с живого прогона.

### Исправлено

- Уведомления и `display-message` подписаны именем цепочки из `chain.json` одной функцией `sign()`
  вместо зашитого «wave-autobot» (#56).
- В уведомлении `BLOCKED`, где нужен владелец, есть класс, `red`, рекомендация, первая строка
  вопроса, варианты и способ ответить (attach или `wab.py say`). Длина не выходит
  за лимит Telegram. Вопрос целиком маскируется путём цитаты волны (`_clean_redact`) до разбора на
  вопрос и варианты: ни разделитель внутри значения секрета, ни невидимый символ в ключе, ни
  разделитель строк не выносят значение открытым. Строка без метки уходит как раньше (#67).
- `state.py where` считает `last_run` по живому `$WAB_DIR/max-runs`. Если файла нет или он испорчен,
  `where` берёт значение из manifest (`init --from-plan` на испорченном файле по-прежнему отказывает
  закрыто, в том числе на числе длиннее лимита `int()`). `fix-loop --accept`/`--defer` из `needs_fix` пересчитывают
  готовность задачи (#60).
- `docs/lessons/2026-10-02-wave-autobot.md`: таблица версий дополнена до 1.0.0. Журнал дефектов #36
  закрыт итоговой таблицей.

## 0.16.0 — 2026-10-04

### Исправлено

- Исчерпанная подписка Astra (Codex App Server) давала `protocol`, а не `quota`: адаптер не знал
  notification `error`, а `turn/completed` со статусом `failed` считал `completion`. Теперь
  `systemError` не обрывает чтение до терминального события, `codexErrorInfo: "usageLimitExceeded"`
  (из `error` и из `turn.error`) даёт `error_category: "quota"`, `error` принимается только для
  текущих thread/turn и никогда не pass; `error` до ответа на `turn/start` тоже распознаётся и не перекрывается успешным `turn/completed` в очереди.
  ([#17](https://github.com/bronxtc52/skill-superarmanda/issues/17),
  [#10](https://github.com/bronxtc52/skill-superarmanda/issues/10))
- `review.py packet` отказывал «diff contains binary changes» на текстовом TSV с ячейкой `-`:
  `numstat` запускался с опциями патча и печатал после статистики сам патч, а поиск `\t-\t` шёл
  по всему выводу. Теперь `--numstat -z` без патча, бинарная запись — только когда первые два
  поля равны `-`.
  ([#8](https://github.com/bronxtc52/skill-superarmanda/issues/8))
- `review.py packet` падал (rc=2) в репозитории с `--object-format=sha256`: bare-представление
  объектов создавалось с SHA-1. Теперь формат берётся у источника.
  ([#2](https://github.com/bronxtc52/skill-superarmanda/issues/2))
- Packet hash: `state.py task-result --packet-hash` принимает и голый 64-hex из `review.py`, и
  `sha256:<hex>`, хранит всегда `sha256:<hex>`; отчёт `review.py run` получил поле
  `state_packet_hash`. Envelope и `packet_hash` старого формата не менялись.
  ([#3](https://github.com/bronxtc52/skill-superarmanda/issues/3))

## 0.14.0 — 2026-10-03

### Добавлено

- Сторож замёрзшего контекста: привязанный журнал и контекст стоят `CTX_FROZEN_TICKS` (5) тактов, а другой
  журнал той же рабочей копии (не принадлежащий другим волнам) растёт — одно событие на эпизод «контекст не
  меряется (сессия не привязана?)», пометка `ctx_frozen` и «⚠ не меряется» на дашборде. Без уведомления. Сторож работает и пока ждёт перепривязки сессии (`await_session`): по последнему
  привязанному журналу и сохранённому контексту; привязка новой сессии кончает эпизод.
  ([#44](https://github.com/bronxtc52/skill-superarmanda/issues/44))
- Цитата волны в уведомлениях: `quote()` и единая отрисовка `render_notice()`. Текст волны и внешний
  текст (`result.md`, `status`, причины гейта и отказов) маскируется без исключения «путь скрипта
  владельца», ограничивается по длине и показывается помеченным («Цитата волны:» / «цитата волны: …»);
  исключение действует только на слова самого диспетчера. Слово с управляющим или невидимым символом
  (Cc, Cf, Zl/Zp) маскируется целиком — он не склеивает и не разрывает секрет; юникодные пробелы Zs —
  разделители слов. Однострочный вид (`_first_line`) цитаты — «Цитата волны: <первая строка>». Охранный тест не пропускает текст волны в
  `put_notice` вне `quote()`.
  ([#32](https://github.com/bronxtc52/skill-superarmanda/issues/32))

### Исправлено

- `quote()`/`render_notice()` маскируют и слово с невидимым default-ignorable символом вне Cf (селектор
  вариантов U+FE0F, U+E0100, CGJ, заполнители хангыля, а также неназначенные в таблицах интерпретатора —
  U+2065, U+FFF0–U+FFF8, U+E0080): `sk-<U+FE0F>ant-…` и `sk-<U+2065>ant-…` больше не выходят видимыми.
- «Волна завершена» больше не оставляет ATTENTION после автозапуска следующей волны: уведомление
  информирующее (`INFO_NOTICES`), а запуск следующей волны диспетчером закрывает ещё открытый сигнал
  `done` предыдущей. ([#55](https://github.com/bronxtc52/skill-superarmanda/issues/55))
- Номер PR волны сохраняется при любом hand-off (вердикт гейта любой, без гейта — best-effort
  `find_pr`): `chain-result.md` больше не пишет «PR: нет», колонка PR дашборда не пустая.
  ([#34](https://github.com/bronxtc52/skill-superarmanda/issues/34))

### Исправлено

- Повтор Enter устаревшего будильника: сначала сверка PR/HEAD, при смене или закрытом PR — очистка
  вместо Enter. ([#31](https://github.com/bronxtc52/skill-superarmanda/issues/31))
- Снижение `max_auto_answers` на ходу при висящем автоответе: ввод очищается, ответ засчитывается в кап.
  ([#50](https://github.com/bronxtc52/skill-superarmanda/issues/50))
- Enter-only повтор доставки выполняет `precheck` под замком ввода; не прошёл — очистка, ответ
  политики засчитывается. ([#53](https://github.com/bronxtc52/skill-superarmanda/issues/53))
- Закрытие окна (`/exit`) не дописывается к недоставленному тексту: под замком ввода, только в пустое
  по экрану поле, иначе очистка, провал — событие и повтор в следующем такте.
- Enter-only повтор будильника заново сверяет PR/HEAD уже под замком ввода (PR закрылся или HEAD сменился
  за время ожидания замка — Enter не жмётся, ввод очищается); ошибка сбора фактов под замком держит
  резерв без Enter и без очистки. Сбой клавиш очистки при закрытии окна не роняет `watch`.

  закрылся или HEAD сменился — ничего не печатается, будильник снимается; ошибка сбора фактов — повтор.
- Закрытие окна: нет рамки ввода (диалог доверия/разрешения, пустой capture) — `/exit` не отправляется,
  `pending_exit` остаётся, одно событие `/exit not sent: no input box` на эпизод.
- Маркер `owner-answered`: статус и штамп снимаются одним снимком; перезапись `status` между чтениями даёт
  маркер без штампа (не совпадает с новым эпизодом), политика отвечает.
- Разбор SGR: `2` внутри составного цвета (`38;5;2`, `38;2;r;2;b`, `38:2::…`) больше не читается как dim.

  `<каталог волны>/max-runs` при запуске волны и при смене в `chain.json`; `init --from-plan` берёт
  лимит в порядке `--max-runs` → `$WAB_DIR/max-runs` → `WAB_MAX_RUNS` → 2, испорченный файл —
  закрытый отказ.
- Подсказка `where` на последнем прогоне больше не уводит нарушения приёмки из fix-loop: они идут
  обычным `fix-loop --outcome failed`, `--defer`/`--accept` — только для находок вне приёмки.
- `where` (`accepted`, `accepted_limitations`) и дашборд считают только принятия, покрывающие
  результат текущего HEAD и дерева; после `resume` старые принятия остаются историей в manifest.
- Тесты не читают и не пишут каталог живого прогона: все переменные `WAB_*` сбрасываются при старте
  наборов и не попадают в подпроцессы; добавлен набор `wab-env-isolation`.
- `init` со счётчиком пишет `runs.json` раньше manifest (резерв прогона) и откатывает его при обычной
  ошибке записи manifest: убитый между записями процесс больше не оставляет неучтённый manifest.
