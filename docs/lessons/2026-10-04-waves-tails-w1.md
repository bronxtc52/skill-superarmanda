# Урок волны W1 цепочки `waves-tails` (2026-10-04): гейт не видел второй прогон

Волна W1 прошла приёмку во втором прогоне (`max_runs: 2`) и записала `DONE`. Гейт мерджа диспетчера
1.0.0 отказал: он сверял PR с заблокированным первым прогоном, а не с текущим. Волна встала в
`BLOCKED`, и дважды подряд auto mode отклонил ручной выход из этого состояния. Ниже — что случилось
и что меняем в скилле, чтобы `BLOCKED` такого рода не повторялся.

## Что случилось

1. Первый прогон W1 упёрся в кап 3/3 (`blocked`). Координатор открыл второй прогон
   (`state.py init --from-plan`, `rec=new_run`). Второй manifest лёг в
   `superarmanda/manifest-run2.json`, оба прогона записаны в `$WAB_DIR/runs.json`.
2. Второй прогон дошёл до готовности: coder, tester и Astra на HEAD, находки приняты
   (`--accept`), задача `ready_for_pr_review`. Волна записала `DONE`.
3. Гейт (`wab.py read_manifest`) читает фиксированный путь `<волна>/superarmanda/manifest.json`,
   а `runs.json` не читает. Там лежал первый прогон, поэтому гейт выдал отказ: `manifest.head ≠ HEAD PR`,
   задача `blocked`, нет coder и tester pass на HEAD.
4. Координатор предложил переставить файлы: первый прогон сохранить как `manifest-run1.json`,
   второй переименовать в `manifest.json`. Auto mode отклонил это дважды («CI Bypass», затем
   «Auto-Mode Bypass»), в том числе после прямого «делай» владельца. Отказ правильный: агент
   правит именно тот вход, по которому гейт решает о мердже. По мандату обходить отказ нельзя,
   поэтому перестановку выполняет владелец руками.

Сухой прогон `gate.manifest_problems` на втором manifest до перестановки вернул пустой список.
Второй прогон был чистым, сломан был только способ найти его manifest.

## Корень

Счётчик прогонов (`max_runs`, `runs.json`, 0.12.0) добавил второй путь к manifest, а потребителя,
который выбирает manifest для гейта, не обновили. Тесты гейта и офлайн-сквозной тест цепочки
проверяли только волну с одним прогоном. Это повтор урока 3 из
`2026-10-02-wave-autobot.md` в другой форме: тесты не видели настоящую форму данных — волну,
у которой больше одного прогона.

## Что меняем

1. **Гейт берёт manifest текущего прогона из `runs.json`.** `read_manifest` читает последний
   прогон волны из `runs.json`. Нет `runs.json` — прежний путь `manifest.json`, для совместимости.
   Повреждённый файл, файл другой волны или отсутствующий manifest — закрытый отказ с причиной, а
   не молчаливый откат на `manifest.json`. Одно место выбора manifest для гейта, дашборда и `where`.
2. **Тест на волну с двумя прогонами.** Юнит-тест гейта: первый прогон `blocked`, второй готов →
   `pass`. Офлайн-сквозной тест цепочки: волна с `max_runs: 2`, где второй прогон доходит до мерджа.
3. **Волна проверяет гейт до `DONE`.** Нужна команда только для чтения (`wab.py gate --dry
   --wave <id>` или `state.py gate-check`): она прогоняет тот же `gate.evaluate` по тому manifest,
   который прочтёт диспетчер. Волна запускает её последним шагом перед `DONE`, а при отказе пишет
   `BLOCKED` с причиной сразу, не дожидаясь гейта диспетчера.
4. **Волна и координатор не переставляют файлы, которые читает гейт.** В `PROTOCOL.md` и
   `references/waves.md` прямо сказать: manifest и `runs.json` пишет только `state.py`. Если гейт
   смотрит не туда, волна пишет `BLOCKED` с готовой короткой командой для владельца (файл
   по короткому пути и показанное содержимое) и не пробует сама: auto mode отклонит, и это
   правильно.
